# Accounts

**Managing the Account is a window over the Workspace you are in, never a screen instead of it**, and so is managing the *Cockpit*: **Platform settings** (Glossary) is on the profile menu after *Settings…*, offered to an admin only and not on a phone, and opens over the Workspace like Settings does, with **Users** and **Usage** as its sections. The header wears the Workspace's colour, holds its *Capture…* control and marks its tab, so an address reached without one had none of that: the chrome fell back to a default theme over a strip with nothing selected, which read as a second, worse header. The Workspaces, the Dashboards and the Types were such addresses; the Types are a section of Settings now, and the other two are gone entirely — a Workspace and a Dashboard are changed on the tab each already has ("Change a workspace or a dashboard on the tab it is", issue 267), and the Types keep a list because they have no tab. Capture is the one screen that is deliberately in no Workspace, and it heads itself rather than borrowing the band. With no Workspace at all there is nothing to draw the app around, and that is a screen of its own beside the logon page: it says so and offers the box to name your first.

**Settings is one window, opened from the profile menu**, between *Signed in as…* and *Sign out*, with the sections *Types*, *Connections* (Gmail and Microsoft Teams), *Agent settings* (the Claude Code connection), *MCP* and *Appearance*. Each section is what its own window used to be and is headed by its entry's name; switching section never closes the window, even while a section is still arriving. It opens on the section asked for, the only one that looks selected and the one focus starts on, and closing it puts focus back on the profile control. *Connections* and *Agent settings* belong to one Workspace at a time, each with a picker that starts on the open one. Coming back from Microsoft or Google after connecting reopens it on *Connections* for that Workspace, saying how it went. Gmail's Connect first opens a window asking which mark to follow — *Labelled `Cockpit`*, chosen each time it opens, or *Starred (flagged in Outlook)* — over the steps that choice needs: for the label, create a label called `Cockpit` in Gmail, sign in with Google past its unverified-app warning allowing Cockpit to change your mail, label a conversation and it becomes a task; for the star, the same sign-in, then star or flag a conversation and it becomes a task, only those starred from now on counting. Cancel there goes nowhere. It is a window over the Workspace and has no address of its own. **On a phone it holds *Appearance* alone**, full screen, and *Settings…* opens on it; the other sections are for a desk, by decision. At a desk it opens on *Types* as asked, with *Appearance* last.

**Agents (Glossary) are chrome, not a window.** Every other Account-wide thing here — the Types — is managed in Settings, a window over the Workspace; Agents are managed from the dock itself, a strip of tiles at the bottom of the screen rather than a list opened from a menu, because an Agent is something you reach for constantly (dropping one on an Item) and only occasionally manage. The dock hides itself: a control at its start puts it away, and a strip as tall as a button, in the same spot at the bottom edge, brings it back; **A** toggles it either way, and no menu does. The dock's own **…**, and a right-click on the dock, offer *Agent settings…*, which opens Settings on that section for the dock's Workspace. The dock is hidden on a phone, where there is no drag; a row's own menu starts any Agent its Dashboard shows, which is the way on a phone and on a keyboard. The dock says how a tile is used — *Drag an agent onto an item to start it.* once Claude Code is connected (hidden on touch), and where it is not, *Connect Claude Code to this workspace, then drag an agent onto an item to start it.* — since a click on a tile opens its form and so reads as something to configure. While an Agent is in the air, rows that take it are faintly tinted with no outline, and the row under the pointer is lit with a solid accent outline and a full tint; Inbox rows, rows with an open run and Agents hidden on that Dashboard are never tinted or lit.

**An Agent starts on a Dashboard row, never an Inbox one** — dropped there, or chosen from the row's menu, where each Agent is named as itself and tagged *Agent* — through the Workspace's Claude Code connection, and the row then carries its **Run** (Glossary) until the Item's Status ends it: Done, To do or Dismiss, with *Undo* bringing it back. The row's menu keeps **Open the Claude session ↗** for as long as the run is open and has no separate *Agent finished*. What Claude is sent is a fixed preamble — the message is its whole task: do exactly what it says and nothing more, run the skill it names and only what the skill covers, ask and wait where answers are needed, and ignore any earlier instruction about the Item, which covers a routine whose saved prompt says otherwise, and begin the first reply with a line `<Agent name>: <Item title>` so the session can be told apart in Claude Code — then the Agent's template filled with the Item's words; the preamble is neither shown nor editable, and *Test again* does not carry it. A new Agent's template begins "Work this item, then stop." so it works out of the box; `{link}` is where the Item came from, or the Dashboard it was started on where it came from nowhere. Every file on the Item follows the template, each a link the session opens without signing in, for an hour; one shown in the description has that link in place of its own address, and a video is only named, since Claude cannot watch it. Starting is never retried by Cockpit, because every retry is another session: an answer that never arrived says *unknown - check Claude* rather than guessing. A start Claude refuses marks the connection failing, said on the dock and on the connection's own row, until a start or *Test again* works.

**A session says when it is waiting on you** through hooks in the Workspace's repository — `Stop` for waiting, `UserPromptSubmit` for working again — which the Claude Code connection's form gives as a snippet carrying that connection's secret, with when a hook last arrived. The row's chip turns amber, and the Agent's tile and the dock count what is waiting. A hook naming no open run, such as another Claude session in the same repository, changes nothing.

**The routine's environment has to be allowed to reach Cockpit's domain**, for the files' links and the hooks alike, and the connection's form asks for it before anything is connected.

**The apps connected to Cockpit over MCP are seen and cut off under *MCP***, a section of Settings — named for the protocol, since that is what claude.ai and every other client calls the address it asks for. The window gives the address to paste into claude.ai — this environment's own origin and `/mcp` — with *Copy*, shown whether or not an app is connected, and one row per app **you** allowed: its registered name, when it was connected and when it last captured. *Disconnect* asks first and ends that app's access, access and refresh tokens both, at once; the Items it captured stay. An app somebody else allowed is not listed, even in the same Account. Not reachable on a phone, whose Settings holds *Appearance* alone.
