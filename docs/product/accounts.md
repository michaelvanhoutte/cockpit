# Accounts

**Managing the Account is a window over the Workspace you are in, never a screen instead of it** — and managing the *Cockpit* is not, which is the one exception and is exactly the distinction: the admin pages (Glossary) are about who exists across every Account, so there is no Workspace behind them to keep and they head themselves the way Capture does. The header wears the Workspace's colour, holds its *Capture…* control and marks its tab, so an address reached without one had none of that: the chrome fell back to a default theme over a strip with nothing selected, which read as a second, worse header. The Workspaces, the Dashboards and the Types were such addresses; the Types are a window now, and the other two are gone entirely — a Workspace and a Dashboard are changed on the tab each already has ("Change a workspace or a dashboard on the tab it is", issue 267), and the Types keep a list because they have no tab. Capture is the one screen that is deliberately in no Workspace, and it heads itself rather than borrowing the band. With no Workspace at all there is nothing to draw the app around, and that is a screen of its own beside the logon page: it says so and offers the box to name your first.

**Agents (Glossary) are chrome, not a window.** Every other Account-wide thing here — the Types, the screen sizes — is managed in a window over the Workspace; Agents are managed from the dock itself, a strip of tiles at the bottom of the screen rather than a list opened from a menu, because an Agent is something you reach for constantly (dropping one on an Item) and only occasionally manage. The open Workspace's **…** carries the one thing that is not a tile's own business — showing or hiding the dock — under a separator at its foot, beside *Manage types*; both are the Account's rather than the Workspace's, and are on that **…** only, never on a tab's own menu. Neither is reachable on a phone, where the **…** is hidden. The dock is hidden on a phone, where there is no drag; a row's own menu starts any Agent its Dashboard shows, which is the way on a phone and on a keyboard.

**An Agent starts on a Dashboard row, never an Inbox one** — dropped there, or chosen from the row's menu — through the Workspace's Claude Code connection, and the row then carries its **Run** (Glossary) until somebody says the agent finished. What Claude is sent is the Agent's template filled with the Item's words; `{link}` is where the Item came from, or the Dashboard it was started on where it came from nowhere. Every file on the Item follows the template, each a link the session opens without signing in, for an hour; one shown in the description has that link in place of its own address, and a video is only named, since Claude cannot watch it. Starting is never retried by Cockpit, because every retry is another session: an answer that never arrived says *unknown - check Claude* rather than guessing. A start Claude refuses marks the connection failing, said on the dock and on the connection's own row, until a start or *Test again* works.

**A session says when it is waiting on you** through hooks in the Workspace's repository — `Stop` for waiting, `UserPromptSubmit` for working again — which the Claude Code connection's form gives as a snippet carrying that connection's secret, with when a hook last arrived. The row's chip turns amber, and the Agent's tile and the dock count what is waiting. A hook naming no open run, such as another Claude session in the same repository, changes nothing.

**The routine's environment has to be allowed to reach Cockpit's domain**, for the files' links and the hooks alike, and the connection's form asks for it before anything is connected.
